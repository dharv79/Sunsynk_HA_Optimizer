### Entry points and data flow

`__init__.py` → `SunsynkOptimizerCoordinator` → `SunsynkOptimizer`

- **`coordinator.py`** owns the `OptimizerState` dataclass (the single source of truth for all runtime state) and persists it via HA's `Store` helper at `.storage/sunsynk_optimizer_state_{entry_id}`. All state mutations go through `coordinator.update_state(**kwargs)`, which also triggers entity refreshes via `async_set_updated_data`. Storage saves are non-blocking (`hass.async_create_task`) via `_async_save_state()`, which catches errors and surfaces them in `last_error`.
- **`optimizer.py`** (since phase 99 the core of a class built from mixins: `opt_overnight` 01:55 plan/retry/watchdog/gentle charge/full-charge day, `opt_daytime` SOC listener/Flux 2/trim/peak cover/peak export/outage, `opt_capture` captures/snapshots/KPIs/daily cost, `opt_reports` weekly/monthly reports and advisors, `opt_monitor` drift/audit/PV strings/inverter events, `opt_events` free and flex events/services, `opt_shadow` shadows; `opt_common` shared helpers) contains all business logic: import plan calculation, Flux 2 export/trim control, full-charge day scoring, free events, peak export/cover, alerts and reports. `async_setup` registers:
  - **Daily time-change listeners:** 01:55 import plan (auto-away check first); 02:20 charge watchdog (phase 22, see import-plan.md); 02:00, 05:00, 16:00 and 19:00 meter snapshots (phase 14, see data-logging.md); 06:00 morning state; 06:05 spare solar; 06:10 tariff price check (phase 33); 06:20 data audit (phase 45); 16:00 peak surplus export (phase 17); 17:00 and 18:00 peak export re-check (phase 66); 18:00 full-charge-day handler; 22:00 day actuals (also the 22:00 meter snapshot); 22:05 Agile dynamic tariff shadow (phase 76).
  - **Intervals:** every 30 minutes (Flux 2 check, peak-window usage, grid charge current restore, peak cover, clipped solar, PV strings, over-limit import, daytime import alert, cost of 1 kWh now); every 2 hours the inverter drift check (also reads inverter fault events).
  - **State changes:** battery SOC (SOC reactions, battery runtime, cost of 1 kWh now) and grid voltage (phase 48 outage open/close).
  - **One-shots:** initial import plan 60 s after setup, spare solar at 90 s, capacity estimate at 120 s when pending; free event and gentle-charge restore timers are re-armed from persisted state.

  The 18:00 handler runs, on Sundays only, full-charge-day selection, `_async_send_weekly_cost_summary` (one JSON line to `CONF_DATA_REPORT_TARGET`; no-op if unset), the shadow scorecard (self-gated to the first Sunday of the month) and the AI weekly insight; then every day the monthly reports (once per month, catch-up) and the full-charge-day re-check. The 60 s initial plan fires on every integration reload, not just first boot. It is **skipped** while a free event holds the slots (`_slots_held`) or when the reload lands in 16:00–19:00, so it can't re-push Flux 2 mid-window. Scheduled callbacks run through `_guarded`, which catches exceptions and surfaces them in `last_error`. `_essential_state(entity_id)` returns `float | None` and is the pre-flight check for battery SOC and forecast availability. `_async_post_with_status(payload)` wraps all income API pushes and returns a bool; `_async_write_setting` is its twin for inverter settings. `_async_track_peak_window_usage` (30-minute tick) snapshots the load/grid daily totals at the first firing in `[16, 19)` and logs the delta at the first firing with hour `>= 19` (`self._peak_window_start`, unpersisted: a restart mid-window skips that day).
- **`planning/`** (package since phase 98; `__init__.py` re-exports every name, so `from .planning import x` is unchanged; modules `core`, `overnight`, `forecast`, `load`, `peak`, `events`, `kpis`, `reports`, `battery`, `shadow`, `redact`; `core` is the dependency sink) holds the HA-free planning maths the optimizer calls into: `select_target_soc` (the full target-SOC branch tree, returning a `TargetDecision`), `apply_soc_adjustments`, bridge/ramp helpers, `resolve_used_charge_rate` (learned-rate + temperature deration), `flux1_end_minutes`, `charge_efficiency` / `window_grid_kwh` (Flux 1 losses and grid kWh), `score_full_charge_day`, and the shared `net_cost_gbp` / `sum_field` / `round_or_none` helpers (also used by `data_logger.py`). New decision logic belongs here, not inline in `optimizer.py`, so it stays unit-testable.
- **`api.py`** handles Sunsynk cloud API calls: RSA-encrypted login (fetches public key → encrypts password with PKCS1v15), bearer token management with automatic re-login on 401, posting to the `/api/v1/plant/{plant_id}/income` endpoint, and reading/writing inverter settings at `/api/v1/common/setting/{inverter_serial}/read|set` (phase 23). Uses the `cryptography` library (not declared in `manifest.json` because it is bundled with Home Assistant itself).
- **`flux_helpers.py`** builds and mutates the `fluxProducts` payload. The two Flux windows are always index 0 (Flux 1, import, `direction=1`) and index 1 (Flux 2, export, `direction=0`). `apply_flux_override()` deep-copies and patches these; `build_payload()` assembles the full income POST body. `merge_entry_data()` is the canonical way to read config — it merges `entry.data` + `entry.options` with options winning, and fills defaults for `charges` and `fluxProducts` if absent.
- **`data_logger.py`**: monthly JSONL logs, pairing and `compute_*` corrections. See data-logging.md.
- **`octopus_public.py`**: Octopus public API (no key) for historic Agile prices (tariff comparison, Agile shadow).
- **Entity platforms** (`sensor.py`, `binary_sensor.py`, `button.py`, `switch.py`, `number.py`, `datetime.py`): see entities-dashboard.md. `entity.py` holds `optimizer_device_info`, the shared device (keyed on `inverter_serial`).
- **`diagnostics.py`**: HA "Download diagnostics" bundle (state, last 7 paired days, merged config), redacted with `planning.redact_config` (phase 45).
- **Services** (`__init__.async_setup`, described in `services.yaml` / `strings.json`): `set_tonight_target`, `skip_tonight`, `schedule_free_event`, `cancel_free_event`, `get_plan` (response only), `probe_inverter_events` (response only). `async_setup_entry` also removes registry entries listed in `const.REMOVED_ENTITY_KEYS`.
- **`card_resource.py`**: `async_register_card` (called from `async_setup`) serves `www/` at `/sunsynk_optimizer_static` and adds each file in `CARD_FILES` with `add_extra_js_url` (`?v=<manifest version>`). Never raises.
- **`www/`**: bundled frontend cards `sunsynk-optimizer-flow-card.js` (`custom:sunsynk-optimizer-flow-card`) and `sunsynk-optimizer-day-chart.js` (`custom:sunsynk-optimizer-day-chart`). See entities-dashboard.md.
- **`dashboard_installer.py`**: generates the Lovelace YAML. See entities-dashboard.md.
- **`config_flow.py` / `const.py`**: config and options flow, constants and defaults. See config.md.

## SOC-path caching (04/11/2026, phase 67)

**Root cause.** `SunsynkOptimizer.cfg` deep-copied the merged config on every access (~20-25 copies per SOC event), `_octopus_band_prices` re-parsed the Octopus rate slots every call, and `update_state(touch=True)` rewrote `updated_at` (a recorder row and a storage save) even when nothing differed.

**Design.** `cfg` returns a cached read-only `MappingProxyType`, rebuilt only when the entry's `data`/`options` objects are replaced (an options change reloads the entry anyway). `_octopus_band_prices` caches per (date, import/export rates entity, each entity's `last_updated`), so it recomputes only when the Octopus sensor updates (max 8 entries). `coordinator.update_state` returns early when `planning.state_fields_changed` finds no difference; a dict/list/set passed back as the same object counts as changed, in case it was mutated in place. A call with no kwargs behaves as before.

**Verification.** `tests/test_state_update_skip.py`; `tests/test_code_integrity.py::test_nothing_mutates_the_cached_config` (AST guard). Behaviour change: `last_updated` no longer moves on a no-change call.
